# Deleting stored files, and the image manager

Part of the froala-uploads-and-storage skill. Event behaviour was reproduced with `froala-editor` 5.6.0 in headless Chromium; the server side used the Node router in server-sdk-node.md.

## Removal events, precisely

| Event | Fires | Argument | Return `false` |
|---|---|---|---|
| `image.beforeRemove` | Before the image plugin removes an image (toolbar remove button, `editor.image.remove()`, Backspace on a selection containing it) | `$img` | Keeps the image |
| `image.removed` | On each `contentChanged`, for every `src` that was in the editor at the previous check and is gone now. Also fires after **redo** re-removes an image | `$img` (detached) | no effect |
| `image.loaded` | On `contentChanged` for a `src` that appeared, including after **undo** restores a removed image | `$img` | |
| `image.replaced` | After an image is replaced (upload over it, image manager). 5.5+ passes the old `src` third. `image.removed` does **not** fire for the old `src` | `$img`, response, old `src` | |
| `file.unlink` | On `contentChanged`, for every `a.fr-file` whose `href` is gone | the `<a>` element | |
| `video.beforeRemove` / `video.removed` | As for images, for `<video>`, `<iframe>` and embeds | `$video` | |

The removal events compare against the list from the previous check. `html.set()` does not fire `contentChanged`, so the list is **not** reset when you load another document.

## Why deleting in image.removed loses data

Both reproduced on 5.6.0 with a handler that called a delete endpoint from `image.removed`:

1. **Undo.** Remove an image (file deleted on the server), then press Ctrl+Z. The `<img>` returns and `image.loaded` fires. It still displays because the browser cached it, but `fetch(src, { cache: 'no-store' })` returned 404, and `editor.html.get()` saves that dead `src`.
2. **Switching documents.** Upload an image, then `html.set('<p>other document</p>')`. Nothing fires. On the next edit, `image.removed` fires for the first document's image, which may still be saved in that document.

The underlying limit: the editor knows what left its DOM, not what your saved documents still reference.

## Recommended: clean up when the document is saved

Let the server decide when a file is unused. On save, compare the uploads referenced by the previous and the new HTML; for each one no longer referenced, delete it only if no other saved document (or kept revision) references it. A soft delete with a grace period (mark now, purge after N days) also covers undo after save.

Helper (Node, tested):

```js
// Names of stored uploads that a saved HTML document references.
const UPLOAD_REF = /\b(?:src|href)="\/uploads\/([0-9a-f-]{36}\.(?:png|jpg|gif|webp|pdf))"/g;
const referencedUploads = (html) => new Set([...html.matchAll(UPLOAD_REF)].map((m) => m[1]));

// On save: files the previous version used and the new version no longer uses.
function unreferencedAfterSave(previousHtml, newHtml) {
  const now = referencedUploads(newHtml);
  return [...referencedUploads(previousHtml)].filter((name) => !now.has(name));
}
```

The pattern matches the names generated by the router in server-sdk-node.md; adapt it to your URLs (S3 `Location`, CDN host). Store the referenced set per document in your database, so "is it used anywhere else?" is a query, not a scan. Files that were uploaded but never saved in any document (the user closed the tab) are found by a periodic job: uploaded more than a day ago and referenced by nothing.

## If you must delete immediately

Delete only files uploaded in this editor session, so loading another document with `html.set()` cannot delete its files. The undo problem remains: tell users that undo cannot restore a deleted image, or soft-delete on the server.

```js
// Delete immediately only files uploaded in this editor session. Read the undo caveat first.
const uploadedHere = new Set();
const deleteStored = (src) => fetch('/api/uploads/delete', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ src }),
});

new FroalaEditor('#editor', {
  imageUploadURL: '/api/uploads/image',
  events: {
    'image.uploaded'(response) {
      uploadedHere.add(JSON.parse(response).link); // response is the raw response text
    },
    'image.removed'($img) {
      const src = $img.attr('src');
      if (uploadedHere.delete(src)) deleteStored(src);
    },
    'image.replaced'($img, response, oldSrc) {
      if (uploadedHere.delete(oldSrc)) deleteStored(oldSrc);
    },
  },
});
```

Tested: replacing an uploaded image deleted the old file; removing all images deleted the session upload and left `/red.png` (inserted with `html.insert`) alone. For files and videos use `file.uploaded` + `file.unlink` (the argument is the `<a>`; read its `href`) and `video.uploaded` + `video.removed`. The server must still check ownership: the browser decides nothing.

## Image manager contract

Plugin `image_manager.min.js` (in the `pkgd` bundles). Opened with the `insertImage` popup's manager button or `editor.imageManager.show()`.

| Option | 5.6.0 default | Notes |
|---|---|---|
| `imageManagerLoadURL` | `'https://i.froala.com/load-files'` | **Froala's demo images.** Always set your own. (The docs show `http://`.) |
| `imageManagerLoadMethod` | `'get'` | |
| `imageManagerLoadParams` | `{}` | Query string for GET, form body otherwise |
| `imageManagerDeleteURL` | `''` | Empty: deleting fires `imageManager.error` code 22 |
| `imageManagerDeleteMethod` | `'post'` | |
| `imageManagerDeleteParams` | `{}` | Added to the delete body |
| `imageManagerPageSize` | 12 | Images rendered per scroll step (the whole list is loaded at once) |
| `imageManagerScrollOffset`, `imageManagerPreloader`, `imageManagerToggleTags` | 20, `null`, `true` | Display only |

**Load response:** status exactly 200 and a JSON array. Each item: `url` (required), `thumb` (recommended; shown in the grid), `tag` (optional, comma-separated tags for the filter), `name` (becomes the `alt`). Every other key becomes a `data-*` attribute on the thumbnail and on the inserted image: `{ "url": "/red.png", "thumb": "/red.png", "name": "Red", "id": "42" }` inserted `<img src="/red.png" data-id="42" data-name="Red" alt="Red" data-url="/red.png" ...>`.

**Delete request:** after the editor's own `confirm()` ("Are you sure? Image will be deleted.") and `imageManager.beforeDeleteImage($img)` (return `false` to cancel), a request with `Content-Type: application/x-www-form-urlencoded` and body `src=<url>`, every `data-*` value (`data-url=...`) and `imageManagerDeleteParams`. The server must answer **200**; anything else (including 204) fires `imageManager.error` code 21 and keeps the thumbnail. On 200, `imageManager.imageDeleted(responseText)` fires.

Both requests carry `requestHeaders`, `withCredentials` when `requestWithCredentials` is set, `Content-Type: application/x-www-form-urlencoded` (even on GET) and, with `requestWithCORS: true` (default), the request header `Access-Control-Allow-Origin: *`. Cross-origin, that header forces a preflight: the server must allow it in `Access-Control-Allow-Headers` (reproduced: a preflight asking for `access-control-allow-origin`), or set `requestWithCORS: false`. A CORS or network failure fires no `imageManager.error`; the manager just stays empty.

`imageManager.error` codes: 10 image cannot be loaded, 11 load request failed, 12 missing `imageManagerLoadURL`, 13 load response is not JSON, 14 missing `thumb` (falls back to `url`), 15 missing `url`, 21 delete request failed, 22 missing `imageManagerDeleteURL`. Other events: `imageManager.imagesLoaded(responseText)`, `imageManager.imageLoaded($img)`.

Tested client configuration:

```js
new FroalaEditor('#editor', {
  imageUploadURL: '/api/uploads/image',
  imageManagerLoadURL: '/api/uploads/images',   // the default is Froala's demo server
  imageManagerDeleteURL: '/api/uploads/delete', // receives src=<url> (form-encoded POST)
  imageManagerDeleteParams: { doc_id: '42' },
  events: {
    'imageManager.imageDeleted'(response) {
      console.log('Deleted on the server', response);
    },
    'imageManager.error'(error, response) {
      console.error('Image manager', error.code, error.message, response);
    },
  },
});
```

Deleting from the manager removes the file for every document that uses it. Check references on the server before deleting, as in the save-time cleanup above.
